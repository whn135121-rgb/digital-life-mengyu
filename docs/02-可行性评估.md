## 0 结论

分三层看，三层结论不同：

| 层次 | 判断 | 说明 |
| --- | --- | --- |
| 愿景 | 成立 | 七件 primitive 确实够用，且已有可运行实现 |
| 成本 | 成立但被乐观化 | 算术无误，假设偏轻；真实成本区间比文章宽 30 倍 |
| 工程 | 对现网基本不适用 | 那套是 DSH-native 独立系统，与 AstrBot 无共同抽象层 |

**打分：路线图可信度 7/10，承诺可信度 3/10。**

一句话：它证明了「需要的东西就这些」，没有证明「这些东西能接到 QQ 上长期活着」。

## 2 主张一：持续数字生命的技术前提（成立）

文章的最小集合是七件：稳定身份、能记、能通信、有地方留东西、能写能跑代码、能上网、有时间（睡/醒/继续）。

对照现网：

| primitive | 梦屿现状 | 缺口 |
| --- | --- | --- |
| 稳定身份 | persona id=7，2101 字 | 无版本化，改动不可追溯 |
| 记忆 | livingmemory，8 条 5573 字 | 全量注入，无衰减/巩固/检索 |
| 通信 | SnowLuma + AstrBot 反向 WS | 仅私聊，无 agent 间通信 |
| 留下东西 | 无独立世界目录 | **完全缺失** |
| 写并运行代码 | `computer_use_runtime=none`，注入 6 个工具 | **无代码执行** |
| 上网 | 有搜索/抓取工具 | 可用 |
| 时间 | proactive_chat 固定倒计时（45 分钟触发、20–180 分钟间隔、23–8 静默） | 有唤醒但无「生活状态」 |

结论：七件里五件有雏形，两件真缺（世界目录、代码执行），一件有但退化（唤醒是定时器不是节律）。**这印证了文章的方向判断**，也解释了为什么现在的她"有生活感但不像在生活"。

## 3 主张二：成本（算术正确，假设乐观）

### 3.1 文章的口径

「每次 5 万 token、每天 100 次、90% 缓存命中 ≈ 1.4 元/天、43 元/月」。

按 DeepSeek Flash 官价复算（非高峰：缓存命中 $0.003 / 未命中 $0.15 / 输出 $0.60 每百万 token）：

- 输入 5.0M，命中 90% → 4.5M × 0.003 = $0.0135
- 未命中 0.5M × 0.15 = $0.0750
- 输出 30k × 0.60 = $0.0180
- 合计 ≈ $0.107 ≈ **¥0.77/天**（高峰价翻倍 ≈ ¥1.53）

**算术没问题**，文章给的 1.4 元接近高峰价下的结果。问题在于三个假设都被当成了典型值。

### 3.2 梦屿的实测（2026-10-26 全天）

数据来自 `qqbot\data\plugin_data\astrbot_plugin_token_usage\usage.db` 的 `daily_usage` 表：

| 项 | 数值 |
| --- | --- |
| LLM 轮次 | 25 |
| 缓存未命中输入 | 96,428 tok |
| 缓存命中输入 | 202,624 tok |
| 缓存命中率 | **67.8%** |
| 输出 | 2,583 tok |
| 单轮平均输入 | ≈ 11,962 tok |
| 成本（Flash 非高峰） | ≈ $0.0166 ≈ **¥0.12** |

换算：即使把轮次提到 100 次/天（她当前 token 结构的 4 倍），日成本也只有 **≈ ¥0.48**，月 ≈ ¥14。

也就是说：**文章假设的「每次 5 万 token」比她实际重 4 倍，「90% 命中」比她实际高 22 个百分点。** 两个假设叠加，才有 12 倍的差距。

### 3.3 仓库自己的反证

README 里有一条署日期的现场记录：两个 agent 开发、测试、交互一整天，DeepSeek 用量约 **¥50**。

这条记录与文章不矛盾，但说明了分界：**陪聊是 ¥0.1–1.5/天，干活是 ¥20–50/天**。差 30–400 倍，取决于 agent 是否在做持续的工程任务。

### 3.4 预算结论

- 按 **60–70%** 缓存命中做预算，不要按 90%
- 闲聊档：¥0.1–1.5/天
- 长任务档：¥20–50/天，必须设日预算熔断
- 夜间批处理放在非高峰窗口（01:00–04:00、06:00–10:00 UTC 为高峰，周一至周五，中国法定节假日除外）

## 4 主张三：工程实现（脚手架，非地基）

### 4.1 已实现（v0.2.0 自述）

- 身份与归属：稳定 `lifeId`、独立 life worker、authority/activity/delegate 三类 Session 归属、Registry/Host 绑定
- 私有空间：独立 Core 与 workspace、owner 绑定的 Memory/Vault/state、文件版本与恢复路径
- 中立共享世界：Supervisor、心跳、逐生命启停、共享资源协调（World 自身不发模型请求）
- 持久通信：人类私聊、agent 间消息、Rooms、Inbox 批处理、回执、时间线、未知结果对账
- 连续与行动：Memory 基础设施、原生工具、Schedule 唤醒、rest/continue 状态、自写上下文检查点、状态恢复
- 委派：后台任务结果/取消/父级通知（默认路由 Codex `gpt-5.6-luna`，DeepSeek 委派默认关闭）
- 本地界面：可运行的 Rooms 网页；Electron 仅含参考源码，无独立安装包

### 4.2 未验证（作者自述的边界）

- 真实 Provider 缓存命中率
- 官方账单登录与扣费
- 外部账号往返（如 B 站 MCP）
- 独立 Electron 安装
- 公开验收仅到「离线测试 + 合成身份的双 worker 本地冒烟 + 浏览器加载检查」

### 4.3 成熟度判断

单人、21 天、24 star、0 fork、0 issue。上游 DSH 是 developer preview，且仓库明确 pin 了 `0.2.0-rc.2`，**上游不承诺兼容该快照**。

这不是缺点，是阶段：它是一套**能跑的实验脚手架**，适合读设计与抄接口，不适合当作三年底座。

## 5 主张四：两处不可信的表述

### 5.1 「灵魂永远不变」

仓库自己写着：`It is not evidence of consciousness.`

真正跨年持久的是磁盘上的东西——`memory.db`、`core.md`、那些文件和 git 历史。模型本身随时会换：十年后 `deepseek-flash` 这个模型名大概率不存在，API 形态也会变。

所以「不变」的着落点是**可迁移的记忆格式**，不是模型，也不是框架。任何把本体绑在某个 runtime 版本上的设计，都会在版本升级那天失效。

### 5.2 「43 元/月」被当成普适结论

它是「聊天级负载 + 乐观假设」的乘积。一旦 agent 开始改代码、跑测试、写游戏，成本会跳一个数量级（见 3.3）。

正确用法：把它当**下界**，不是预算。

## 6 抛开 AstrBot / SnowLuma 的可行性

### 6.1 结论：完全可行

理由有三：

1. **生命层不属于消息框架**。身份、记忆、调度、世界、多生命，AstrBot 本来就不是为此设计的；把它挪出去，是回归职责，不是额外成本。
2. **QQ 只是 I/O**。可以换成 NapCat/LLOneBot 桥、Telegram、网页，甚至本地 CLI。换掉 AstrBot 不等于换掉她。
3. **接口比框架长寿**。只要消息信封、记忆 schema、世界目录格式这三样定死，底层用什么跑都可以换。

### 6.2 三件真正卡人的事（与框架无关）

| 卡点 | 性质 | 对策 |
| --- | --- | --- |
| 腾讯风控 | 平台约束 | 单号、低频、不群发、失败退避；网关层限速 |
| 模型 API 生命周期 | 外部依赖 | 模型适配层 + 记忆格式与模型解耦（embedding 可重算） |
| 持续唤醒成本 | 经济约束 | 日预算熔断 + 缓存命中监控 + 非高峰批处理 |

### 6.3 保留 QQ 的取舍

| | 保留 QQ | 放弃 QQ |
| --- | --- | --- |
| 社交语境 | 保住（她「在你的 QQ 里」） | 失去，需要重建在场方式 |
| 技术自由 | 受限（协议桥不可控） | 完全自由 |
| 风控风险 | 有 | 无 |
| 工作量 | 中（只换生命层） | 大（连在场方式一起重做） |

选定：**保留 QQ，只把生命层搬出去。**

## 7 目标架构

```
QQ NT ──Hook── SnowLuma ──OneBot WS──┐
                                     ▼
                    ┌────────────────────────────┐
                    │ gateway（极薄，可替换）      │
                    │ 收发 / 白名单 / 分段 / 限速  │
                    └─────────────┬──────────────┘
                                  │ 本地 HTTP + 队列（唯一长期契约）
                    ┌─────────────▼──────────────┐
                    │ life-runtime（独立进程）     │
                    │ identity / memory / sched   │
                    │ world(fs) / workers / tools │
                    └────────────────────────────┘
```

AstrBot 只占 gateway 一格，且随时可换。本体在 runtime 里。

### 7.1 关键决策

| 要素 | 选择 | 理由 |
| --- | --- | --- |
| agent loop | 自建轻 loop（OpenAI 兼容 + 工具调用），约 400 行 | 模型可换、行为可读、不被框架版本锁死 |
| 调度 | 单 scheduler 进程 + SQLite jobstore + 心跳文件 | 治现网最痛点：重启丢任务、热重载不触发 `on_astrbot_loaded` |
| 记忆 | 独立 SQLite（nodes/edges/events/rooms/usage）+ JSONL 导出 | schema 是资产，embedding 可重算 |
| 通信契约 | envelope：`id, from, to, ts, kind, payload, receipt` | 唯一需要十年不变的东西 |
| 世界 | 普通文件系统 `world/`，git 可版本化 | 「她留下的东西」必须能直接打开 |
| gateway | 现在 AstrBot 插件；未来 NapCat/自建 | 换通道只改一个文件 |

### 7.2 为什么不直接依赖 DSH

接口照它学，依赖不照它抄。三条理由：

1. 上游是 developer preview，pin 的 rc 版本不保证兼容；
2. 自建 loop 只有几百行，换来「三年后还能读、还能改」的控制权；
3. 记忆与世界是本体资产，不该由框架的 Session 语义定义。

## 8 迁移路线（绞杀者模式）

原则：**每步可单独回滚，她任何时刻都不能「不在」。**

### P0 · 并行运行（3–5 天）

不碰对话链路，只做「非对话」：

- `life/runtime/` 一个 Python 进程（复用 `qqbot\AstrBot\.venv` 解释器，不新装环境）
- `life/world/` 目录 + `heartbeat.json` + `journal/2026-10-26.md`
- 每天 21:00 生成 3 件「自己的事」并把产物落盘
- AstrBot 侧加一个 `life_state` 只读工具（约 10 行注册）

验收：**第二天她自己提起「昨天那个小游戏我改了第二关」**。这一句出现，连续性成立；不出现，后面全白搭。

### P1 · 记忆搬家（1–2 周）

- livingmemory 的节点/边迁到独立库
- **runtime 成为唯一 writer，AstrBot 只读**
- 50+ cron 收进单 scheduler，加健康滞后自检

### P2 · 换 gateway（2–3 周）

- AstrBot 退化为 I/O 适配器，或换 NapCat + 自建 OneBot 客户端
- 对话主链路进 runtime，此后 AstrBot 可下线

### P3 · 第二个生命

- 两个 worker 各自 identity/memory，经 `world/rooms/` 与 inbox 通信

### P4 · 长期演进

- schema 版本号 + 迁移脚本
- 模型适配层（flash → 其它）
- 年度归档 `world/archive/2026/`

## 9 风险与对策

| 风险 | 触发信号 | 对策 |
| --- | --- | --- |
| 腾讯风控 | 发送失败率上升、掉线 | 单号低频、退避、网关限速 |
| 成本跳变 | 日成本 > 预算阈值 | 熔断、降级为纯聊天、夜间批处理 |
| 缓存命中下滑 | 命中率 < 60% | 稳定前缀、把状态追加在尾部、监控 `prompt_cache_hit_tokens` |
| 双写不一致 | 她记起两套矛盾的事 | 单写者原则：runtime 独占写，其他只读快照 |
| 调度静默停摆 | 主动消息突然消失 | 单 scheduler + 持久化 jobstore + 心跳文件 |
| 框架版本锁定 | 升级后不兼容 | 不把本体绑在 DSH 版本上；自建 loop |
| 人格漂移 | 说话风格变化 | 人格版本化，改动留档可回滚 |

## 10 验收判据

分三档，都要可观测：

**一句话级（1–2 天）**
- 她主动提起昨天自己做过的事，且细节正确

**一天级（1 周）**
- 主动消息不再全部来自定时器（至少 1/3 由状态触发）
- 夜间产物可在 `world/` 里直接打开

**一周级（1 个月）**
- 记忆库有巩固产物（摘要节点），且原始节点可追溯
- 日成本稳定在预算内，缓存命中 ≥ 60%
- 重启后 5 分钟内恢复全部调度

### C 复算方法

```
命中成本 = 命中 token / 1e6 × 0.003
未命中成本 = 未命中 token / 1e6 × 0.15
输出成本 = 输出 token / 1e6 × 0.60
总成本 = 三者之和（美元），× 7.2 折算人民币
```

### D 术语

- **primitive**：构成持续存在所需的最小能力单元（身份、记忆、通信、文件、代码、网络、唤醒）
- **envelope**：进程间消息信封，长期契约
- **绞杀者模式**：新系统逐步接管旧系统职责，旧系统最后下线
- **单写者**：同一份状态只允许一个进程写入，其余只读
